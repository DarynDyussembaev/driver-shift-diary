# Дневник смен водителя

Небольшое приложение: сводка и список поездок водителя за день, переключение дней, добавление поездки.

- **Бэкенд** — Python, FastAPI, данные в JSON-файле.
- **Веб-клиент** — React + TypeScript, Vite.
- **Мобильный клиент** — Flutter (Android, iOS, веб), работает с тем же API. Подробности в [mobile/README.md](mobile/README.md).

## Как запустить

### Через Docker

Нужен только Docker.

```bash
docker compose up --build
```

- приложение: http://localhost:8080
- API и Swagger: http://localhost:8000/docs

Добавленные поездки лежат в томе `trips-data` и сохраняются между перезапусками. Вернуть исходные данные: `docker compose down -v`.

Тесты в контейнере:

```bash
docker compose run --rm --no-deps backend pytest
```

Flutter-клиент в браузере (по желанию, первая сборка долгая — образ с Flutter SDK весит несколько ГБ):

```bash
docker compose --profile flutter up --build
```

Откроется на http://localhost:8081.

### Без Docker

Нужны Python 3.11+ и Node.js 20+.

### 1. Бэкенд

```bash
cd backend
python -m venv .venv
.venv\Scripts\activate          # Windows
# source .venv/bin/activate     # macOS / Linux
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000
```

API: http://127.0.0.1:8000, документация Swagger: http://127.0.0.1:8000/docs

### 2. Фронтенд

Во втором терминале:

```bash
cd frontend
npm install
npm run dev
```

Приложение: http://localhost:5173. Запросы к `/api` Vite проксирует на бэкенд.

### 3. Тесты

```bash
cd backend
pytest
```

## Что сделано

### API

| Метод | Путь | Что делает |
|---|---|---|
| `GET` | `/api/days` | Дни, за которые есть поездки |
| `GET` | `/api/days/{YYYY-MM-DD}` | Список поездок и сводка за день |
| `POST` | `/api/trips` | Добавить поездку |

Пример ответа `GET /api/days/2026-10-01`:

```json
{
  "date": "2026-10-01",
  "summary": {
    "trips_count": 2,
    "revenue": 3900,
    "commission": 585,
    "net": 3315,
    "cash": {"count": 1, "amount": 1500},
    "card": {"count": 1, "amount": 2400}
  },
  "trips": [
    {"id": "t1", "start": "2026-10-01T08:10:00+05:00", "end": "2026-10-01T08:32:00+05:00",
     "amount": 2400, "payment": "card", "commission": 360}
  ]
}
```

`net` — «на руки»: выручка минус комиссия.

### Проверка данных при добавлении

`POST /api/trips` возвращает `422`, если:

- сумма не больше нуля;
- окончание не позже начала (сравниваются моменты времени, а не строки);
- время передано без смещения (`+05:00`);
- способ оплаты не `cash` и не `card`;
- комиссия отрицательная или больше суммы.

### Защита от дублей

Клиент генерирует `id` поездки один раз и повторяет его при повторной отправке.

| Ситуация | Ответ |
|---|---|
| Новая поездка | `201`, поездка сохранена |
| Тот же `id`, те же данные | `200`, возвращается уже сохранённая поездка |
| Тот же `id`, другие данные | `409` |
| `id` другой или не передан, но все поля совпадают | `200`, возвращается уже сохранённая поездка |

Проверка и запись идут под одним локом, поэтому два одновременных одинаковых запроса тоже не создадут дубль.

### Клиент

- сводка за день: «на руки», число поездок, выручка, комиссия, наличные/карта;
- список поездок с временем, длительностью и способом оплаты;
- переключение дней: стрелки, выбор даты, быстрые кнопки для дней с поездками;
- форма добавления с проверкой на клиенте; комиссия подставляется как 15% от суммы, её можно изменить.

### Тесты

`backend/tests` — 26 тестов:

- `test_summary.py` — расчёт сводки, пустой день, разбивка наличные/карта, граница дня;
- `test_duplicates.py` — повторная отправка в разных вариантах, запись в файл, перезапуск сервера;
- `test_validation.py` — проверка входных данных.

`mobile/test` — 20 тестов Flutter-клиента: форматирование, проверка формы, работа с API, экран.

## Решения и допущения

- **К какому дню относится поездка.** К локальной дате её начала, в том смещении, которое записано в самой поездке. Поездка в `00:30+05:00` относится к этому дню, хотя по UTC это ещё предыдущий.
- **Деньги — целые числа.** Суммы хранятся в тенге без копеек, как в примере данных, чтобы не было ошибок округления.
- **Хранение.** `backend/data/trips.json` — исходные данные. При первом запуске сервер копирует их в `trips.local.json` (в `.gitignore`) и пишет уже туда. Запись идёт через временный файл с подменой. Путь к файлу можно задать переменной `TRIPS_FILE`.
- **Часовой пояс формы.** Новые поездки создаются со смещением `+05:00` (константа `TZ_OFFSET` в `frontend/src/format.ts`).

## Что не сделано

- Форма не умеет добавлять поездку, которая переходит через полночь (API такую примет).
- Нет редактирования и удаления поездок, нет авторизации — один водитель.
- JSON-файл подходит для одного процесса сервера; для нескольких нужна БД с уникальным ключом.
- Тестов на React-клиент нет.
- Flutter-клиент проверен анализатором, тестами и веб-сборкой; на Android и iOS не запускался.
